# 저장소 ADK 문서의 2.x 격차 점검 (v1.26.0 → v2.14.0)

> 대상: 이 저장소의 `google-adk/planreact-planner/`, `google-adk/agent-tool/`, `google-adk/web-server/` 문서 11개
> (총 1,757줄). 모두 **ADK Python v1.26.0**(태그 `427a983b`) 기준으로 작성됐다.
> 비교 기준: **v2.14.0** (`main` @ `1cb926d`). 점검일 2026-11-09.
> 방법: 문서가 인용한 소스 경로 15개를 양쪽 버전에서 받아 diff하고, 문서의 주장 단위로 대조했다.
> **1.x 라인은 v1.39.1(2026-08-27)에서 동결**됐으므로(→ [릴리스 현황](../releases/v2.14.0_릴리스_개발운영_현황.md))
> 이 문서들을 읽는 사람은 더 이상 기능이 추가되지 않는 트랙을 보고 있다.

판정 3단: **그대로** = 2.14.0에서도 서술이 맞다 · **주의** = 결론은 유효하나 세부·경로·전제가 달라졌다 ·
**틀림** = 2.14.0에서 서술이 거짓이 된다.

## 1. 틀림 — 전제가 깨진 것

### 1-1. PlanReActPlanner가 태그를 **텍스트에서 제거**한다

`planners/plan_re_act_planner.py`에 1.26.0에는 없던 `_strip_planning_tags`가 생겼고,
비-함수호출 파트를 처리할 때 **`response_part.text`를 태그 없는 문자열로 덮어쓴다**.

```
# v2.14.0
_PLANNING_TAGS = (PLANNING_TAG, REASONING_TAG, ACTION_TAG, REPLANNING_TAG)

if response_text and response_text.startswith(self._PLANNING_TAGS):
    response_part.text = self._strip_planning_tags(response_text)   # ← 1.26.0에는 없음
    self._mark_as_thought(response_part)
```

1.26.0은 같은 자리에서 **thought 마킹만** 하고 텍스트는 그대로 뒀다. reasoning 블록도 마찬가지로
`_strip_planning_tags`를 거친다.

- `FINAL_ANSWER_TAG`는 `_PLANNING_TAGS`에 없으므로 **최종답변 태그는 지워지지 않는다.**
- 영향: `PlanReActPlanner_분석보고서.md`의 핵심 요약("태그 블록 내용을 편집하지 않음"),
  `단계2_응답파싱`, `단계3_스텝전환_thought언마킹`(다음 턴에 재노출되는 평문의 형태가 달라짐),
  `단계별_프롬프트_응답_트레이스`, 그리고 **`PlanReActPlanner_태그내용변화.drawio`**(누적 표의 내용 자체).

### 1-2. OOM 문서의 수정 버전 매트릭스 2행이 낡았다

`AgentTool_SkillToolset_OOM_원인분석.md` §5는 두 수정을 "모든 릴리스 ❌ (v2.5.0까지) · **main만 ✅**"로
기록했다. v2.14.0에서 **둘 다 릴리스에 들어와 있다**.

| 결함 | 문서 기록 | v2.14.0 실제 | 근거 |
|---|---|---|---|
| skill 리소스 오류 무한 재시도 (#5652) | v2.2.0부터 ✅ | ✅ | `tools/skill_toolset.py`에 `RESOURCE_NOT_FOUND_FATAL` |
| load_skill 후 빈 응답 (#6225) | main만 ✅ | **✅ 반영됨** | `skill_toolset.py`의 지침 문구 — "오류가 나면 턴을 끝내지 말라", "로드 직후 빈 응답으로 턴을 끝내지 말라" |
| AgentTool이 자식 오류를 `''`로 삼킴 (`e737f229`) | main만 ✅ | **✅ 반영됨** | `tools/agent_tool.py`가 `last_error_message`를 모아 `return last_error_message or ''`, 텍스트가 없으면 오류 메시지 반환 |

→ §6 완화책의 전제가 바뀐다. **`SafeAgentTool`로 `e737f229`를 백포트하는 대목은 2.x에서는 불필요**하고,
자식 instruction에 #5652/#6225 규칙을 손으로 넣는 보조책도 upstream 지침과 중복된다. 1.x에 머무는
환경에는 문서가 그대로 유효하므로, **"1.x 환경 / 2.x 환경" 두 열로 가르는 것**이 맞다.

### 1-3. `AdkWebServer`는 deprecated다

```python
# cli/adk_web_server.py (v2.14.0, 36줄)
@deprecated("AdkWebServer is deprecated and has been refactored into ApiServer and DevServer. Use DevServer instead.")
class AdkWebServer(DevServer):
  """Deprecated wrapper class around DevServer for backward compatibility."""
```

실제 구현은 `cli/api_server.py`(2,808줄)와 `cli/dev_server.py`(1,863줄)로 갈라졌고,
`cli/service_registry.py`·`cli/trigger_routes.py`·`cli/agent_test_runner.py`가 새로 생겼다.
문서 두 개(`AdkWebServer_세션_라이프사이클_메모리분석.md`, `AdkWebServer_잔존실행_관측_구현명세.md`)는
모두 **하위호환 래퍼를 가리키고 있다.** 세션·메모리 분석의 결론 자체는 `Runner` 쪽이라 살아 있지만,
"어디를 보라"는 지시가 어긋난다.

## 2. 주의 — 결론은 살아 있고 세부가 달라진 것

**PlanReAct**

1. **첫 함수호출 그룹 수집 버그 수정**: `if first_fc_part_index > 0:` → `>= 0`. 1.26.0에서는 **첫 파트가
   함수호출이면 뒤따르는 함수호출 그룹을 수집하지 못했다.** 문서의 "첫 (그룹) 함수호출까지 보존" 서술은
   2.x에서 비로소 정확하다.
2. reasoning 텍스트 끝에 남던 `/*FINAL_ANSWER*/` 분리자를 2.x는 떼어낸다(`_split_by_last_pattern`은
   분리자를 왼쪽에 포함시킨다). `단계4` 문서의 split 설명에 한 줄이 필요하다.
3. `_mark_as_thought`가 `if response_part.text:` → `is not None`으로 바뀌어 **빈 문자열도 thought로
   마킹**된다.
4. **동적 지침 라우팅**(`flows/llm_flows/prompt/_dynamic_instructions.py`)이 생겼다. 지침을
   system_instruction 대신 user content로 보낼 수 있어 "system 지침은 매 스텝 동일하게 재부착(정적)"의
   예외가 된다. 다만 `FeatureName.DYNAMIC_INSTRUCTION_ROUTING`은 `EXPERIMENTAL` + **`default_on=False`**라
   기본 경로는 그대로다.
5. **프로세서 순서가 한 칸 바뀌었다.** 요청 프로세서 10개와 응답 프로세서 2개는 동일하지만 배치가 다르다.
   1.26.0 `compaction → contents → cache → interactions` / 2.14.0 `compaction → interactions → contents → cache`.
   ("체인 id를 contents 앞에서 뽑는다"는 주석이 근거) 문서는 interactions/cache를 다루지 않으므로 추가 설명이
   필요한 쪽이다.

**AgentTool**

6. `mode`별 변종이 생겼다 — `_SingleTurnAgentTool`, `_TaskAgentTool`(+ `_DefaultTaskInput`). 둘 다
   **`mode='chat'`인 `LlmAgent` 전용**이고 `ctx.run_node`로 실행된다. 즉 **격리 Runner를 쓰지 않는 경로가
   생겼다.** `LlmAgent.mode`(`chat`/`task`/`single_turn`)는 2.x 신설 필드이고, 기본값은 서브에이전트면
   `chat`, 워크플로 노드면 `single_turn`이다. 문서의 "AgentTool = 격리 Runner"는 **기본 `AgentTool`에만**
   해당한다.
7. 부모의 컨텍스트 캐시 설정이 자식에게 전달되며 TTL이 **300초로 상한**된다(`_MAX_CHILD_AGENT_CACHE_TTL_S`).
8. `_ForwardingArtifactService` → **`ForwardingArtifactService`**(공개 이름). 파일 경로는 같다.
   자식이 부모 아티팩트를 읽어야 하면 자식 `tools`에 `load_artifacts_tool`을 넣으라는 안내가 추가됐다.

**WebServer**

9. 플러그인 콜백이 12개 → **14개**(`on_agent_error_callback`, `on_run_error_callback` 추가, 제거 없음).
   `잔존실행_관측_구현명세`의 RunTracker 판정은 "after_run이 finally가 아니다"를 이용하는데, 2.x에는
   **오류 경로 전용 콜백이 있으므로 더 단순하게 판정할 수 있다.**
10. **성장 벡터 (B) SSE 끊김 미처리가 해소됐다.** `cli/api_server.py`에 `_monitor_client_disconnect`가 있고,
    ASGI 수신 채널에서 `http.disconnect`를 보면 "Client disconnected. Aborting agent run for session %s."를
    남기고 런을 중단한다.
11. **성장 벡터 (C) 요청당 전체 히스토리 로드에 1급 완화책이 생겼다.** `RunConfig.get_session_config`로
    `GetSessionConfig(num_recent_events=…, after_timestamp=…)`를 넘기면 세션에서 가져올 이벤트를 제한한다.
    1.26.0 `runners.py`에는 `get_session_config`가 **0건**이었다(서명도 `(user_id, session_id)`뿐).

**공통**

12. **`flows/llm_flows` 모듈이 서브패키지로 재편됐다.** 기존 경로는 전부 **하위호환 shim**으로 남아 import는
    되지만, "이 파일에 코드가 있다"는 서술은 틀린다.

| 문서가 인용한 경로 | v2.14.0 실제 위치 |
|---|---|
| `flows/llm_flows/instructions.py` | `flows/llm_flows/prompt/_instructions.py` |
| `flows/llm_flows/contents.py` | `flows/llm_flows/context/_contents.py` (+ `_compaction`, `_fencing`, `tools/_rearranger`) |
| `flows/llm_flows/_nl_planning.py` | `flows/llm_flows/extensions/_planning.py` |
| `flows/llm_flows/compaction.py` | `flows/llm_flows/context/_compaction.py` |
| `flows/llm_flows/context_cache_processor.py` | `flows/llm_flows/context/_cache.py` |
| `flows/llm_flows/interactions_processor.py` | `flows/llm_flows/context/_interactions.py` |
| `flows/llm_flows/identity.py` | `flows/llm_flows/prompt/_identity.py` |
| `cli/adk_web_server.py` | `cli/api_server.py` + `cli/dev_server.py` |

## 3. 그대로 유효한 것

- 태그 5종(`/*PLANNING*/`, `/*REASONING*/`, `/*ACTION*/`, `/*REPLANNING*/`, `/*FINAL_ANSWER*/`)과
  **thought 마킹 → 다음 스텝 언마킹** 2단 구조. `PlanReActPlanner` 자체에 deprecated·experimental 표시 없음.
- 요청 프로세서에서 **지침이 identity보다 먼저** 붙는 순서(`_instructions` → `_identity`).
- 기본 `AgentTool`의 **격리 실행** — 새 `Runner` + `InMemorySessionService()`, `InMemoryMemoryService()` 폴백,
  `ForwardingArtifactService`로 아티팩트 전달, 자식 `state_delta`를 부모 `tool_context.state`로 역전파,
  `skip_summarization`·`include_plugins` 의미 동일.
- 세션 스냅샷 설계 — `InMemorySessionService`가 `copy.deepcopy`로 내보내는 구조 유지.
- **성장 벡터 (A)**: `InMemorySessionService`에 evict·TTL·상한이 **여전히 없다**(2.14.0 기준 검색 0건).
- OOM 문서의 결함 사슬 서술과 #5652 가드(v2.2.0+) 기록.

## 4. 재작성 범위 제안

| 순위 | 작업 | 분량 추정 |
|---|---|---|
| **P0** | 영향 문서 5개 진입점에 **"이 문서는 1.26.0 기준, 2.x 차이는 이 점검 문서 참조"** 한 줄 추가 | 5줄 |
| **P1** | `web-server/` 2개 — 헤더에 deprecated 경고 + `ApiServer`/`DevServer` 대응, (B)(C) 해소 반영, 콜백 14개 기준으로 RunTracker 판정 단순화 메모 | 중 |
| **P1** | OOM §5 매트릭스를 **"1.x / 2.x" 두 열**로 재작성, §6 완화책에서 2.x 불필요 항목 표시 | 소 |
| **P2** | PlanReAct 핵심요약 + `단계2`·`단계3`·`단계4`에 태그 제거 동작 반영, `태그내용변화.drawio` 갱신 | 중 |
| **P3** | AgentTool 동작분석에 `mode` 변종(격리되지 않는 경로)·캐시 TTL·공개 클래스명 추가 | 소 |
| **P4** | 전 문서 경로 일괄 치환(위 대응표) | 소 |

**전면 재작성은 권하지 않는다.** 1.26.0 기준 분석은 그 버전에 머무는 환경에 여전히 유효하고, 실측
(weakref/gc, OOM 재현)은 그 버전에서 수행된 1차 자료다. 버전 꼬리표를 분명히 달고 2.x 차이를
덧붙이는 편이 근거를 잃지 않는다.

## 5. 점검 방법과 한계

- diff한 파일: `planners/plan_re_act_planner.py`, `tools/agent_tool.py`,
  `tools/_forwarding_artifact_service.py`, `flows/llm_flows/single_flow.py`, `plugins/base_plugin.py`,
  `runners.py` — v1.26.0 원본을 받아 v2.14.0 클론과 비교했다.
- 심볼 확인만 한 파일: `tools/skill_toolset.py`(2,946줄), `models/lite_llm.py`(5,410줄),
  `cli/api_server.py`, `cli/dev_server.py`, `sessions/in_memory_session_service.py`,
  `agents/llm_agent.py`, `sessions/base_session_service.py`. **전체 diff는 뜨지 않았다.**
- **2.x에서 재현 실측은 하지 않았다.** OOM 재현·weakref/gc 관측은 1.26.0 결과이며, 위 "해소" 판정은
  **코드 존재 확인**까지가 근거다.
- `freebuff/`·`mcp/`·`agent-skills/`는 이 점검 대상이 아니다.
