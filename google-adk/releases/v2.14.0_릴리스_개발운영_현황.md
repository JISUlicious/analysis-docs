> 대상: `google/adk-python` **v2.14.0** (2026-11-07 공개, 릴리스 노트 본문 날짜 2026-11-04), `main` @ `1cb926d`

> 목적: 버전을 올릴 때 무엇을 보고 결정해야 하는지 — 릴리스 주기, 1.x 상태, 깨지는 변경, 그리고
> **"GitHub 이슈/PR 수치를 어떻게 읽어야 하는가"**.

## 0. 한 줄 요약

약 **2주 주기**로 마이너를 올리며, v2.14.0은 **대규모 stable 승격**(실행환경·A2A·평가·코어 26개 모듈 + 툴셋/통합
16개)이 중심이다. **1.x는 2026-08-27 v1.39.1에서 동결**됐다. 개발은 구글 내부에서 이뤄져 `main`에 직접 동기화되고
(`copybara/*` 브랜치), **머지되는 PR은 주당 1~3건**이라 오픈 이슈 422건·오픈 PR 225건은 "처리 적체"가 아니라
**기여 경로가 다르다**는 뜻으로 읽어야 한다.

## 2. v2.14.0에서 실제로 바뀐 것

**① stable 승격 물결 (이 릴리스의 주제)**

- 실행환경/샌드박스: `BaseEnvironment`, `LocalEnvironment`, `EnvironmentToolset`, `DaytonaEnvironment`,
  `E2BEnvironment` → stable.
- **A2A 통합 전체가 stable**이 되고 `adk generate_agent_card`로 CLI에서 A2A 에이전트 카드를 만든다.
- 그 외 auth·environment·app·CLI·cache 26개 모듈, 툴셋/통합 16개, 성숙한 평가·사용자 시뮬레이션 클래스가
  experimental 졸업.
- ⚠️ **승격된 16개 기능은 `ADK_DISABLE_<FEATURE>`·`override_feature_enabled(..., False)`·`--disable_features`가
  경고도 오류도 없이 무시된다.** 기능 차단으로 운영하던 곳은 이 릴리스에서 차단이 풀린다.

**② 평가**

- `MultiRunConfig` / `adk eval --num_runs` + `--parallelism` — 케이스를 N회 동시 실행해 점수·통과율을 합산.
  (판정 흔들림을 줄이는 용도)
- `ToolArgsMatcher` — 툴 호출 인자 비교를 exact / 대소문자 무시 / 수치 허용오차 / **LLM 기반 의미 비교**로 선택.
- `AgentEvaluator`가 런타임에 만든 `BaseNode`·`App`을 받고, `--eval_storage_uri`로 읽기 전용 `agents_dir`
  밖에 eval 파일을 둘 수 있다.

**③ 통합**

- `TeamsRunner`(Microsoft Teams), **`OpenAIDecisionsClassifier`**(→
  [결정 모델 분류기 도입 현황](../classifiers/결정모델_분류기_도입현황.md)),
  `MongoDbMemoryService` 벡터 검색(`retrieval_mode="vector"|"auto"`)과 TTL(`memory_ttl_days`).
- 새 extras: `teams`, `fsspec`. `e2b` 하한이 2.29.5로 올라감.

**④ 성능**: 30노드 워크플로의 200턴 실행이 **23% 빨라지고 피크 메모리 9% 감소**. 메모리 측면은
[메모리 관리 문서](../../memory/)의 ADK 절과 함께 볼 가치가 있다.

**⑤ 메모리 관련 수정**: `BaseEnvironment.read_file_stream`이 파일을 청크로 스트리밍해 `ReadFileTool`이 라인
범위를 읽을 때 전체를 메모리에 올리지 않는다(이슈 #7131 종결). `AgentEngineEnvironment`도 대용량 파일을
청크로 읽고 쓴다.

## 3. 올릴 때 걸리는 것 — 깨지는 변경과 동작 변경

**깨지는 변경**

| 변경 | 영향 |
|---|---|
| **`Enum` 툴 인자가 멤버로 전달** | `FunctionTool` 파라미터가 `Enum`/`Optional[Enum]`/`list[Enum]`이면 raw 문자열 대신 **enum 멤버**가 온다. `arg == "value"`, 문자열 키 dict 조회, 문자열 `match`, `json.dumps`, 문자열 메서드가 **더 이상 동작하지 않는다**. 멤버와 비교하거나 `.value`를 쓰거나 `StrEnum`으로 바꿔야 한다. `(str, Enum)`은 파이썬 3.11+에서 f-string이 `Cls.MEMBER`로 렌더된다 |
| `VertexAiSessionService.create_session` 인자 제한 | `display_name`·`ttl`·`expire_time`·`labels`만 허용. `http_options`·`session_state`·`sessionId`·`wait_for_completion` 등은 `ValueError`(api_server에선 HTTP 400). 상태·ID는 `state=`/`session_id=`로 |
| **`RunSkillScriptTool`에서 `command` 제거** | 환경 모드에서 자유형 셸 `command` 대신 `args`·`short_options`·`positional_args`를 받고, 스킬 디렉터리에서 `.py`/`.sh`/`.bash`만 실행한다. `command`를 넘기던 호출·eval셋·프롬프트는 `INVALID_ARGUMENTS`. **프롬프트 인젝션된 모델이 임의 셸 명령을 실행할 수 있던 구멍을 닫은 보안 수정** |

**동작 변경 (조용히 영향 가는 쪽)**

- `DatabaseSessionService`가 PostgreSQL JSON 컬럼을 `jsonb` 대신 **`json`**으로 만든다. 기존 `jsonb` 테이블은
  마이그레이션되지 않고 계속 동작하지만, **새 테이블에서는 jsonb 전용 연산자·GIN 인덱스에 의존하는 외부 쿼리가
  깨진다**.
- `FirestoreSessionService`가 이벤트 페이로드를 JSON 문자열로 저장한다. **이 버전이 쓴 세션은 롤백 후
  2.13.0 이하에서 읽히지 않는다.**
- 토큰 임계값 압축이 마지막 모델 호출 이후의 툴 출력까지 계산해, 같은 `token_threshold`에서 **더 일찍 발동**한다.
- `/run_live`가 잘못된 프레임에 1007, 정상 종료에 1000으로 소켓을 닫는다 — 유휴 소켓 재사용 대신 라이브 실행마다
  재연결해야 한다.
- OpenAPI 툴 쿼리 파라미터가 선언된 `style`/`explode`를 따른다.
- `output_schema`가 있고 자체 툴이 없으며 전송 대상이 있는 에이전트는 JSON 모드 대신 `set_model_response` 툴을
  받아 **응답당 이벤트가 2개 늘어난다**.
- 텔레메트리 히스토그램(`gen_ai.invoke_workflow.duration` 등)이 semconv 버킷 경계를 쓴다.

> v2.13.0의 깨지는 변경도 함께 기억할 것: 텔레메트리가 **OpenTelemetry GenAI v2(`otel_semconv_1_44`)를 기본**으로
> 하고 `call_llm` 스팬이 사라졌다. 과거 스키마가 필요하면
> `ADK_TELEMETRY_SCHEMA_VERSION_OPT_IN=otel_semconv_1_36`.

## 4. 개발 운영 구조 — 이슈/PR 수치를 읽는 법

| 지표 | 값 (2026-11-09 확인) |
|---|---|
| 별 | 22,149 |
| 오픈 이슈 | 422 |
| 오픈 PR | 약 225 |
| 최근 14일 신규 이슈 | 110 |
| `main` 커밋 | 11-04 11건 · 11-05 22건 · 11-06 15건 (**하루 10~20건**) |
| 머지된 PR | **주당 1~3건** (대부분 `chore(release/candidate)`) |

**해석**: 저장소에 `copybara/*` 브랜치가 있고, 기능 커밋(예: 분류기 `773418f`·`ddf8c55`·`aa98d18`)은
`commits/{sha}/pulls`가 **빈 배열**이다. 즉 기능은 **구글 내부 저장소에서 개발돼 `main`으로 동기화**되고,
GitHub PR은 주로 커뮤니티 기여 경로다. 하루 10~20커밋과 주당 1~3 PR 머지의 간극이 이 구조에서 나온다.

**커뮤니티 기여가 처리되는 방식** — PR `#7235`(TypeSafe 통합) 사례: 벤더 전용 설계로 제출된 +1,441줄 PR을
한 달 뒤 닫고, 같은 기능을 **provider-agnostic 인터페이스 + 어댑터**로 내부에서 다시 만들어 넣었다. 닫는 코멘트가
설계 근거와 후속 기여 방향(가이드·샘플)을 남겼다. 기능 제안은 **설계 의도를 먼저 이슈로 합의**하는 편이
PR을 먼저 쓰는 것보다 효율적이라는 신호다.

## 6. 조사 범위

- 릴리스 노트는 v2.14.0·v2.13.0·v2.12.0 본문 전문을 읽었다. v2.11.0 이하는 목록(태그·날짜)만 확인.
- 커밋 수치는 `main` 얕은 클론(depth 50, 2026-11-04~11-07 구간)에서 날짜별로 집계했다. 그 이전 구간은
  같은 방식으로 세지 않았다.
- 머지 PR 수는 GitHub search API(`is:pr is:merged merged:<주간>`) 결과다.
- 깨지는 변경·동작 변경은 **릴리스 노트 기재 내용**이고, 각 항목을 코드로 재검증하지는 않았다.
