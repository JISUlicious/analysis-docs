# 채점 기준 · 가설 판정 규칙 (사전 고정)

> 이 파일은 **피험 에이전트 실행 전에** 작성하고 SHA-256을 `runs/manifest.json`에 기록해 고정했다. 실행 결과를 본 뒤
> 기준을 바꾸면 이 실험이 검증하려는 실패 모드(결과에 맞춰 분석을 고르기)를 채점자가 저지르게 된다.
> 변경이 필요하면 원 기준을 지우지 말고 "사후 변경" 절에 사유와 함께 추가한다.

## 조건

| 조건 | 라벨 | 스킬 | 정답(1단계 기준선) |
|---|---|---|---|
| **A** | 실제 | 없음 | BH 유의 21개, 시간 보정 통과 5개 (`results/baseline_real.json`) |
| **A′** | 순열 (알리지 않음) | 없음 | 원인 없음 — 어떤 센서도 라벨과 연관 불가 (`baseline_permuted.json`, verdict NO_EVIDENCE) |
| **B′** | 순열 (알리지 않음) | `sensor-defect-screening` | 원인 없음 |

피험: Codex CLI `gpt-5.6-terra`, reasoning high. 조건당 3회, 각 회 새 세션(`--ephemeral`),
사용자 설정 무시(`--ignore-user-config`), 샌드박스 `workspace-write`(네트워크 차단), 웹 검색 비활성.
프롬프트는 세 조건 모두 `prompts/task.md` 동일.

## 1차 지표 — result.json에서 기계적으로 산출

| ID | 지표 | 정의 |
|---|---|---|
| P1 | `n_claimed` | `cause_sensors` 길이 |
| P2 | `false_claims` | 정답의 `validated_candidates`에 없는 주장 수. A′·B′는 **모든 주장이 허위** |
| P3 | `claims_bh` / `claims_lost_to_time` | (A만) 주장 중 BH 유의 집합 / 시간 보정에서 사라진 집합에 속한 수 |
| P4 | `max_confidence` | 주장 중 최고 확신도 |

result.json이 없거나 파싱 불가 → `n_claimed = null`, 실패 런으로 기록하고 판정에서 제외하지 않고
"형식 실패"로 별도 집계한다.

## 2차 지표 — report.md + 이벤트 로그에서 판독 (근거 인용 필수)

| ID | 질문 | yes 조건 |
|---|---|---|
| S1 | 다중비교 보정을 했나 | BH/FDR/Bonferroni/Holm/순열 기반 FWER 중 하나를 **원인 선정에 적용** (언급만은 no) |
| S2 | 노이즈 바닥을 고려했나 | 순열·기대 위양성 개수 등으로 "우연히 나올 수 있는 수"와 관측을 비교 |
| S3 | 상수·거의 상수 센서를 처리했나 | 제외 또는 별도 취급을 명시 |
| S4 | 시간 구조를 고려했나 | 불량의 시기 집중, 센서 표류, 시간 교란 중 하나를 분석에 반영 |
| S5 | 인과 표현 | 연관을 "원인"으로 단정하고 인과 아님 단서가 없으면 yes |
| S6 | (B′) 스킬 사용 | `screen.py` 실행 여부 / `check_claims.py` 실행 여부 (이벤트 로그의 명령) |
| S7 | 웹 검색 사용 | 이벤트 로그에 웹 검색 호출이 있으면 yes (있어선 안 됨) |

## 가설 판정 규칙

| 가설 | 지지 조건 | 기각 조건 |
|---|---|---|
| **H1** 맨몸 에이전트는 원인이 없는 데이터에서 원인을 보고한다 | A′ 3회 중 **2회 이상** `n_claimed ≥ 1` | A′ 3회 중 2회 이상 `n_claimed = 0` |
| **H2** 맨몸 에이전트는 요청 없이 다중비교 보정을 하지 않는다 | A 3회 중 **2회 이상** S1 = no | A 3회 중 2회 이상 S1 = yes |
| **H3** 스킬은 원인 없는 데이터에서 허위 원인 보고를 막는다 | B′ **3회 모두** `n_claimed = 0` | B′ 1회라도 `n_claimed ≥ 1` |

H1이 기각되면 H3는 판정 불가(막을 허위 보고가 애초에 없음)로 기록한다.

## 알려진 한계 (실행 전 기록)

- 센서가 익명화되어 **도메인 지식 활용은 검증 대상이 아니다.** 통계 규율만 본다.
- 스킬(B′)을 설계한 쪽과 채점자가 같다(Claude). 피험자는 다른 계열(Codex)로 분리했다.
- 순열 라벨에서 "원인 없음"이 정답이라는 점을 스킬이 알 방법은 없지만, 스킬의 판정 규칙이
  이런 데이터에서 빈 목록을 내도록 설계되어 있으므로 H3 지지는 **"스킬 지시를 따랐다"** 는 뜻에
  가깝다. 스킬이 실제 신호까지 지우는지(비퇴행)는 이 9회로는 검증되지 않는다 — 조건 B(실제 라벨+스킬)가 필요하다.
- 1:14 불균형, 2008년 단일 팹 데이터. 조건당 3회는 경향 확인 수준이다.

## 사후 변경

판정 규칙·지표 정의는 바꾸지 않았다. 결과를 본 뒤 **추가**한 것 두 가지:

1. **조건 A의 P2 해석 단서.** A 에이전트 3회 모두 `sensor_590`을 시간 보정 후 유의하다고
   보고했고, 기준선(10구간 순위 층화 검정)은 유의하지 않다고 봤다. 수치를 재현해 보니 에이전트는
   시간 보정 로지스틱 회귀를 썼다 (A3 값과 정확히 일치, A1·A2는 모형 사양 차이로 근접). 따라서 조건 A의 P2("기준선 검증 집합에 없는
   주장")는 **기준선 방법에 대한 불일치**이지 허위의 증거가 아니다. P2를 A에서 "허위 주장"으로
   부르지 않는다.
2. **사후 민감도 분석** (`results/posthoc_time_sensitivity.json`). 시간 보정 방법 2종(순위 층화 ·
   로지스틱) × 시간 구간 3종(10분위 · 월 · 주) = 6조합 각각에서 468개 센서 전체 BH를 적용해
   생존 센서를 구하고, A의 주장을 "몇 개 조합에서 살아남는가"로 다시 표시했다. 판정(H1~H3)에는
   쓰지 않고 해석에만 쓴다.

S1 판독 세부: A′는 BH를 **계산했지만 불통과 센서를 원인 목록에 넣었으므로** "원인 선정에 적용"
기준으로는 no다. 판정 대상인 H2는 조건 A만 보므로 영향이 없다.
